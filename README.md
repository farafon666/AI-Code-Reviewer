# AI Code Reviewer

Приложение рассчитано на локальное использование одним пользователем или
доверенными локальными процессами. Для backend и CI используется Node.js 24.
Аутентификация не реализована; наружу API публиковать не следует.

## Локальный запуск без Docker

Установите Ollama и запустите сервер в отдельном терминале, если он ещё не работает:

```sh
ollama serve
```

В другом терминале загрузите модель до запуска backend:

```sh
ollama pull qwen2.5-coder:7b
```

Установите зависимости через `npm ci` в каталогах `backend`, `apps/remote` и
`apps/host`. В отдельных терминалах запустите `npm start` в каждом из этих
каталогов. Backend и оба dev server слушают только `127.0.0.1`. По умолчанию
backend обращается к `http://127.0.0.1:11434` и использует
`qwen2.5-coder:7b`. Для другой модели задайте `OLLAMA_MODEL` в `backend/.env` и
заранее загрузите её через `ollama pull <имя-модели>`. Адрес сервера можно изменить
через `OLLAMA_BASE_URL` в том же файле. Полный пример настроек находится в
`backend/.env.example`; скопируйте его в `backend/.env` при необходимости.
Локальную Ollama оставляйте привязанной к loopback, без `OLLAMA_HOST=0.0.0.0`.

Откройте http://localhost:3000. Remote можно открыть отдельно на
http://localhost:3001.

Frontend использует относительный адрес `/api/review`. Оба webpack dev server
проксируют `/api/*` на `http://127.0.0.1:5000/*`. Host также проксирует
`/remote/*` на `http://127.0.0.1:3001/*`, включая `remoteEntry.js` и чанки.

## Запуск через Docker Compose

```sh
docker compose up --build
```

Откройте http://localhost:3000 (host) или http://localhost:3001 (remote).

Порты интерфейсов публикуются только на `127.0.0.1`. Порты backend (`5000`)
и Ollama (`11434`) не публикуются на хосте: обращения к ним идут через внутреннюю
сеть Compose. Только внутри контейнера backend слушает `0.0.0.0`.

Compose ждёт успешного healthcheck Ollama, затем запускает одноразовый сервис
`ollama-init`. Он проверяет наличие модели и автоматически загружает её, если она
отсутствует. Backend запускается только после успешного завершения подготовки.
По умолчанию используется `qwen2.5-coder:7b`. Первый запуск требует доступа к
реестру моделей и может занять время; прогрев модели в память не выполняется.

Для выбора другой модели создайте `.env` в корне проекта рядом с
`docker-compose.yml`:

```dotenv
OLLAMA_MODEL=qwen2.5-coder:1.5b
```

Compose передаёт это значение и загрузчику, и backend. Корневой `.env` используется
для Docker Compose; при запуске без Docker настройки backend берутся из
`backend/.env`.

Модели сохраняются в volume `ollama_data`. При повторном запуске уже доступная
модель используется без повторного скачивания. `docker compose down` сохраняет
volume, а `docker compose down -v` удаляет его вместе с моделями.

Посмотреть состояние сервисов и ход подготовки:

```sh
docker compose ps -a
docker compose logs -f ollama ollama-init
```

Если Ollama недоступна, проверка готовности блокирует запуск зависимых сервисов.
Если загрузка модели завершается ошибкой, `ollama-init` выходит с ненулевым кодом,
а backend не запускается. После устранения причины (например, ошибки имени модели
или доступа к реестру) повторите `docker compose up --build`.

В контейнерах маршрутизацию выполняет Nginx:

| Публичный путь                   | Внутренний адрес                  |
| -------------------------------- | --------------------------------- |
| `/api/review` на host или remote | `http://backend:5000/review`      |
| `/remote/remoteEntry.js` на host | `http://remote:80/remoteEntry.js` |
| `/remote/<chunk>.js` на host     | `http://remote:80/<chunk>.js`     |

## Ограничения review API

CORS отключён: оба интерфейса работают через same-origin proxy. При наличии
`Origin` API принимает только `http://localhost:3000`, `http://127.0.0.1:3000`,
`http://localhost:3001`, `http://127.0.0.1:3001`. Запросы без `Origin` разрешены
для локальных CLI. Это не заменяет аутентификацию.

`POST /api/review` принимает несжатый `application/json` с непустой строкой
`code` и возвращает `{ "review": "..." }`. При прямом обращении к backend путь
остаётся `/review`. Исходный код не исполняется; ESLint разбирает его в отдельном
worker thread. Превышение времени анализа завершает worker. Общий дедлайн или
отключение клиента отменяют запрос к Ollama, включая ожидание первого токена.
Автоматических повторов LLM-запроса нет. Отчёт ESLint сокращается с явной пометкой.

| Переменная env                | По умолчанию | Назначение                                              |
| ----------------------------- | -----------: | ------------------------------------------------------- |
| `JSON_BODY_LIMIT_BYTES`       |       262144 | JSON-тело, 256 КиБ; учитывает экранирование строк       |
| `MAX_CODE_BYTES`              |        32768 | Исходная строка в UTF-8 до обработки, 32 КиБ            |
| `MAX_CODE_LINES`              |         1000 | Строки; LF, CRLF и CR считаются одинаково               |
| `REVIEW_RATE_LIMIT_MAX`       |            5 | Все попытки POST review за одно окно                    |
| `REVIEW_RATE_LIMIT_WINDOW_MS` |        60000 | Окно ограничения частоты, мс                            |
| `MAX_CONCURRENT_REVIEWS`      |            1 | Активные review; очереди нет                            |
| `REVIEW_TIMEOUT_MS`           |       300000 | Общий дедлайн анализа и LLM, мс                         |
| `ANALYSIS_TIMEOUT_MS`         |         5000 | Максимальное время worker ESLint, мс                    |
| `ANALYSIS_MEMORY_MB`          |          128 | Предел old-generation heap worker, МиБ                  |
| `ANALYSIS_MAX_FINDINGS`       |           20 | Замечания ESLint в отчёте и prompt                      |
| `ANALYSIS_MAX_OUTPUT_BYTES`   |         4096 | Максимальный отчёт ESLint в UTF-8, включая пометку      |
| `LLM_NUM_CTX`                 |        32768 | Контекст модели, токены; требует соответствующей памяти |
| `LLM_MAX_OUTPUT_TOKENS`       |         2048 | Максимальная длина генерации                            |
| `HTTP_REQUEST_TIMEOUT_MS`     |        30000 | Время получения запроса backend, мс                     |
| `HTTP_RESPONSE_TIMEOUT_MS`    |       330000 | Ожидание ответа frontend и idle timeout backend, мс     |

При локальном запуске настройки берутся из `backend/.env`; в Docker задавайте
эти переменные в корневом `.env` рядом с Compose. Некорректные числа блокируют
запуск. Таймаут анализа не должен превышать общий дедлайн, а таймаут ответа должен
покрывать сумму дедлайна review и времени получения запроса. Бюджет генерации
должен быть меньше контекста. Размер тела должен быть не меньше размера кода.

Лимит частоты и слоты общие для обоих интерфейсов и всех IP, хранятся в памяти
одного процесса и сбрасываются при перезапуске backend. Неудачные и отклонённые
из-за занятости попытки POST также расходуют лимит; запрещённый Origin отклоняется
раньше. При `429` возвращается `Retry-After`. Для занятого слота это минимальная
задержка перед новой попыткой, а не обещание завершить текущий review за секунду.

`GET /api/review/limits` возвращает действующие ограничения для интерфейса и не
расходует квоту review. Frontend показывает эти значения, проверяет размер ввода,
обрабатывает HTTP-ошибки и отменяет ожидание после настроенного таймаута ответа.

Ошибки backend имеют формат `{ "error": "..." }`:

| Статус | Причина                                             |
| ------ | --------------------------------------------------- |
| `400`  | Некорректный JSON или `code`                        |
| `403`  | Запрещённый Origin                                  |
| `413`  | Превышен размер тела, кода или количество строк     |
| `415`  | Не JSON, сжатое тело или неподдерживаемая кодировка |
| `422`  | Превышено время или ресурсы статического анализа    |
| `429`  | Превышена частота или заняты все слоты              |
| `502`  | Ошибка обращения к Ollama                           |
| `504`  | Истёк общий дедлайн review                          |

Nginx и dev proxy ожидают ответ 330 секунд. Nginx ограничивает тело 256 КиБ и
ожидание данных тела 30 секундами. При повышении соответствующих env-лимитов
согласуйте их с настройками обоих `nginx.conf` и `webpack.config.js`.
Большой файл может превышать контекст модели даже при допустимом размере в байтах;
для таких файлов используйте меньшие фрагменты или подходящую модель и контекст.

## Проверка

В каталоге `backend` выполните `npm test`. Тесты используют HTTP-заглушку Ollama,
проверяют таймауты до первого токена и посреди потока, отмену при отключении
клиента, освобождение слотов, валидацию, rate limit и завершение зависшего worker.
Загружать модель для тестов не нужно. В CI также собираются оба frontend и
проверяется `docker compose config --quiet`.

После установки зависимостей всех трёх приложений выполните из корня
`node --test test/dev-proxy.test.js`. Этот тест проверяет оба dev proxy: обычный
ответ, отмену review при отключении клиента и освобождение слота для следующего
запроса. Он также запускается в CI.
